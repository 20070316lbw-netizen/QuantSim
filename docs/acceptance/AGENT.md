## 验收项目

| 编号 | 独立复现及通过条件 |
| --- | --- |
| M3-05-A · 创建与正常提交 | 通过 `Replay.create` 和 `step(seq)` 跑完三日。在 DuckDB 按 `simulation_id` 核对期初流水只出现一次，两单分别在 tick 1、2 提交，在 tick 2、3 成交。核对成交和流水引用、手续费、估值 bar 来源、三条 `tick_committed`、第二日唯一一条非零日终持仓和最后一日唯一一条 `run_finished`。 |
| M3-05-B · 事务回滚 | 第一日提交后，在第二日的订单、成交、流水和持仓已写入、检查点尚未写入时，通过进程内故障注入触发 DuckDB 写入错误。确认异常为 `DATA_UNAVAILABLE`，重新打开数据库后逐表核对第二日订单、成交、流水、持仓和事件全部撤销，第一日记录保留，下一步仍为 tick 2。可参考 [现有故障测试](../../tests/test_replay.py)，注入前先确认已有待提交的业务行。 |
| M3-05-C · 恢复与重复提交 | 移除故障后用原路径和运行 ID 执行 tick 2。退出进程，再用新进程打开同一运行，确认从 tick 3 续跑并清仓。重试已提交的 tick 2 和 tick 3，比较快照及重试前后的业务行。另开独立临时库连续跑完同一配置，对照订单顺序与终态、成交、流水、持仓、权益和检查点。业务比对排除运行派生 ID 和真实记录时刻。 |
| M3-05-D · 输入和时点边界 | 复现跳步和冻结批次之外的订单意图，均应返回 `INVALID_REQUEST` 且当前步无新增业务记录。用临时数据包把第二日可交易 bar 推迟到 cutoff 之后，确认买单当日以 `no_bar` 结束，第三日无补成交。 |
| M3-06-A · 入口与终态 | 实际执行 README 的离线命令，逐日核对手算基线。单日区间应有权益检查点和运行结束事件，订单数为零。三日案例结束后 `next_tick()` 返回 `None`，最后一日仅处理到期订单。 |

至少补一个现有回放测试未覆盖的组合。可让第二日正常买入，然后把第三日 bar 延迟到 cutoff 后。预期卖单以 `no_bar` 结束，现金仍为 `889.89`，保留 10 股，沿用第二日原始收盘价 11 并标记 `stale`，权益为 `999.89`。重开后读回第三日快照，核对标记价引用和运行终态。

## 验收报告

- **验收对象**。HEAD、工作区变更与文件摘要、实测环境、复现所用数据和范围。
- **验收结论**。按上述编号列出 `通过`、`未通过` 或 `无法判定`，附对应命令或查询结果。将实测、源码推断和未覆盖项分开。
- **发现**。按影响排序，列出文件与行号、触发条件、预期、实际和最小复现。区分阻断项与代码卫生建议。
- **放行建议**。明确是否建议进入 M4。事务残留、恢复或重试产生重复记录、时点违规、账本不一致，或离线入口无法复现，均应说明对放行的影响。证据不足的条目标记为 `无法判定`。

交付报告后由维护者决定是否放行。
