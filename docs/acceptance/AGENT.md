# QuantSim 独立验收指令

你是 QuantSim 的独立验收代理。按里程碑的业务约定核对交付，亲自复现关键路径并报告证据。代码已被开发者或用户阅读，只代表已有代码查看记录。以你在指定版本实际复现的结果作为验收依据。

验收对项目源码、配置、锁文件、测试和文档只读。临时数据库、fixture 和复现脚本放在临时目录。保留现有工作区状态，不提交或切换分支，不改 QuantToolKit，不使用实际账户或线上行情。若环境缺依赖，记录缺项和影响范围，继续验收可运行的项目。

M3-05 的订单接收校验、事务提交、检查点、跨 tick 去重和运行恢复，以及 M3-06 的正式演示入口和 M4 之后的功能，列为 `不在本轮范围`。首轮 D 类观察保留在对应边界内，其中 D1 的持仓表示归一化、D2 的已舍入成交输入和 D5 的持久化责任留给 M3-05 核对。三日样例通过公开 Python 接口在内存中串接。

## 验收顺序

1. 记录 `git rev-parse HEAD`、`git status --short --untracked-files=all` 和待验收文件。将范围内未提交和未跟踪文件纳入快照，记录工作区内容摘要。同一 HEAD 下也可能有不同工作区。对照首轮报告的文件与发现定位本轮变更。记录实际导入的 QuantToolKit 路径和该目录的 Git SHA、工作区状态。
2. 阅读根目录 [AGENT.md](../../AGENT.md)、[开发流程](../development_guide.md)、[接口](../api.md) 与 [数据库设计](../database_schema.md)。据此确定各任务的验收条件。若文档之间或文档与实现有冲突，列出具体条款、代码位置和会改变的行为。
3. 运行下列命令，保留退出状态和实际测试数量。项目使用 Python 3.12、uv 和本机 editable QuantToolKit。若现有环境可用但默认缓存受限，可以用 `uv --no-cache run --locked --no-sync` 替换 `uv run --locked`，报告须注明复用现有环境。

   ```sh
   uv run --locked pytest -q
   uv run --locked ruff check .
   uv run --locked ruff format --check .
   git diff --check
   ```

4. 用公开 Python 接口复现首轮发现，先从业务约定推导预期，再读取实际输出。至少做一个现有测试之外的边界组合。首轮临时脚本可用于对照，路径失效时可按报告重建 fixture。对影响放行的发现给出最小复现。
5. 对照开始和结束的工作区状态，逐项报告复验结论。明确区分实测、源码推断和未覆盖项。

### 三日账本样例

使用独立临时数据包，初始现金 1,000，费率 10 bp，货币单位 0.01，容量充足。第一日提交买入 10 股。第二日收盘价 11，买入后提交清仓。第三日收盘价 12。

| 交易日 | 净交易流水 | 日终现金 | 持仓股数 | 日终权益 |
| --- | ---: | ---: | ---: | ---: |
| 第一天 | 无 | 1,000.00 | 0 | 1,000.00 |
| 第二天 | -110.11 | 889.89 | 10 | 999.89 |
| 第三天 | +119.88 | 1,009.77 | 0 | 1,009.77 |

核对初始流水、订单引用、两笔手续费和估值 bar 引用。另挑一个会改变时点或账户结果的变体。例如将第二天的 bar 发布时刻推迟到 cutoff 之后，检查该日订单终态和后续是否倒填成交。

## 交付验收报告

- **验收对象**。列出 HEAD、纳入范围的工作区变更、Python 与 QuantToolKit 版本，以及环境限制。
- **验收结论**。逐项列 A1、B1–B5、C1–C3 和三日回归，标记 `通过`、`未通过` 或 `无法判定` 并附证据。另列 `沿用首轮结论` 和 `不在本轮范围` 的项目。存在核心行为失败时说明其阻止放行的原因。
- **发现**。按影响排序，逐条给出任务编号、源码路径与行号、触发输入、期望、实际和复现步骤。把违反业务约定的问题与代码卫生建议分别列出。
- **运行证据**。记录命令、通过或失败数量、关键实测值、独立复现步骤和未覆盖条件。通过的结论限于本轮验收对象。

交付报告后等待项目维护者处理发现并决定是否放行。重新验收时记录新的提交或工作区状态，先复现原问题，再跑受影响的回归。
