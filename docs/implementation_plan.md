# QuantSim 实施计划

完整的 M0–M9 产品路线、任务单和验收流程见 [开发流程说明书](development_guide.md)。本文保留 M0–M5 的早期技术拆解及 M1、M2 的交付记录。

Phase 0 交付源码审计、70 项登记能力清单、模块接口、数据库草案和实施顺序。人工审查通过后从 M1 开始。

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| M1 项目骨架与接入验证 | 初始化 QuantSim Python 3.12 / uv 工程，锁定 Toolkit 审查后的 Git SHA。加入 DuckDB 首版 migration、只读行情仓库、固定离线 fixture 和 Adapter 的查询及最小特征转接 | macOS 本机新环境锁定安装，运行 pytest。合成行情经过 DuckDB 长表、公开行情准备、`historical_return` 到领域结果。重复键、来源遗失、错误价格列、未来可用性和禁用能力得到预期结果 |
| M2 历史市场 | 证券身份、历史代码、交易日历、证券池、行情与财报导入、完整性检查、版本和逐值来源。规范化行情、研究与模拟快照分层 | 给定日期、证券池和字段，能读取时点快照并回到归档证据。复权、退市、改码、披露、缺行、版本和事件冲击有独立验收 |
| M3 最小回放 | 实现 Clock、Scenario、Strategy、Execution、Portfolio 与协调器。用少量已知价格的日频 fixture 跑空仓、买卖与场景暂停 | 决策最早下一 tick 成交。覆盖假期、提前收盘、迟到 bar、零成交量、缺 bar、容量不足、现金/可卖量不足、场景同时间排序、过期、末日和零交易。故障注入验证 tick 回滚及重放，检查订单、成交、流水、持仓和权益守恒 |
| M4 策略与绩效 | 通过 Adapter 调用动量、波动、合成分数、调仓日和等权持有基准。接入连续收益、总收益、夏普、最大回撤、胜率及事件报告，落下 `experiments`、`backtest_runs` | 同一数据/配置重放产出相同业务行及统计。权益与工具箱结果逐期对照，异常收益、基准缺值、少样本、非有限值、空成交和错误报告类型有确定行为 |
| M5 离线研究与终端演示 | 接入未来标签、IC、样本切分和 LightGBM，离线验证通过后允许预训练推理。用本机界面展示回放、订单、净值和研究结果 | 标签/结束日与训练截止一致，预测特征列顺序和时点一致。回放端无法调用标签或训练。界面从只读状态消费，界面退出或报表失败可恢复 |
| 后续扩展 | 按需接入[分钟行情](api.md#分钟行情预留)，评估真实时点历史、公司行动、借券及多空、限价单、部分成交与向量化研究回测编排 | 每项先明确数据与交易规则，再新增用例。分位多空需具备相应空头账本和限制。事件回放与向量化结果各自标注执行口径 |

M3 仍按日频验收。设计回放协调器时，以 `tick.seq` 标识已提交的回放步骤，保留独立的 tick 经济时点和可见性 cutoff。日频 tick 的经济时点是当日收盘，分钟回放可在同一 `session_date` 内推进多个 tick。日终持仓和权益仍按交易日记录。

## M1 审查后执行顺序

1. 在 QuantSim 建立最小 Python 项目与 uv 环境，直接依赖 DuckDB、实际使用的 pandas 和固定 SHA 的 QuantToolKit。以可访问 Git 源作为锁定来源，使用本机路径调试时保持为临时覆盖。锁定安装验证 Apple Silicon 和原生依赖。将新包和测试都放在 QuantSim。
2. 以 [database_schema.md](database_schema.md) 的 DDL 为草案建立 migration。测试空库初始化和重复启动。导入少量精确可手算的 bar 与显式日历，验证版本冻结、外键、批次重导入、复权和不可成交标记。
3. 实现 [api.md](api.md) 中行情读取的最小接口和 Adapter 能力查询。固定第一个公开计算绑定，使用真实 Toolkit 通过来源检查。调用前截断时点，执行负窗口/偏移用例，确认错误消息保留原异常链。
4. 记录锁文件、离线 fixture 和测试结果，提交人工复查。先完成 M2 历史市场，再在 M3 接入时钟、撮合与账本。

## 交叉验证

- **Adapter** 以实际公开包装器做集成测试。测试合格对象可用、复制后严格入口拒绝、外部行情重新登记、来源失效不能改变语义、标签和远期价差进不了策略和净值通道。测试签名与清单变化时能指出能力名。
- **时序与成交** 用同一事件和行情序列测试逐日执行及中途恢复。修改未来 bar，已提交策略决策和账本应保持一致。验证没有可用行情时不会倒填成交，估值用 stale 且有来源。
- **数据库** 检查外键、稳定业务键、相同批次导入、失败回滚和提交后重试。运行时间字段和运行 ID 从业务等价比较中剥离。验收一个含 0 持仓日、开仓、清仓、停牌日和费用的手算序列。
- **研究与报告** 与相同输入的 Toolkit 直接调用对照，校验单位、缺失值、年化口径和报告所需产物。模型测试分开核对日期隔离、实际标签结束时点与训练可见性。

## 人工审查项

- 确认以单市场、单币种、无公司行动的冻结 fixture 启动，首版只做多、整数股及下一交易日收盘成交。确认费用和容量参数、缺价估值处理。
- 确认运行时复用的 Toolkit 修订版本和可复现安装来源，以及独立 DuckDB 文件和导入范围。
- 确认策略受限能力、来源重接入规则、tick 事务和表结构。上述范围确认后进入 M1。

## M1 验证记录

- macOS arm64 / Python 3.12.13，从空环境执行 `uv sync --locked` 成功。Toolkit 以 Git SHA `94532f91e0708ca20713b7660477da130e1aa6d6` 安装。锁定环境实测 DuckDB 2.0.0、pandas 3.1.1、LightGBM 4.7.0 和 Torch 2.15.0。
- QuantSim 22 项测试通过，Ruff lint、format 与锁文件检查通过。构建 wheel 时包含 SQL migration。README 示例使用公开 Toolkit 包装器，从收盘价 10 到 11 得到历史收益 0.1。
- 使用同一锁定环境运行 Toolkit 源码树测试，285 项通过。额外用已安装的 Toolkit 包直接运行上游仓库测试时，284 项通过，1 项摄取脚本测试依赖源码仓库的默认数据路径。QuantSim 使用自己的显式数据路径和数据库。
- 行情批次清单与行情改为在同一 DuckDB 事务保存。当前建表入口见 [schema.sql](../src/quantsim/schema.sql)。

## M2 交付

- M2-01 至 M2-06 通过稳定证券身份、历史代码、上市区间、显式交易日历、交易状态和证券池变更建模。JSON 历史包在事务内归档、校验及规范化。
- M2-07 至 M2-10 通过 `snapshot`、`MarketView`、冻结批次查询与逐值来源实现。研究层使用带独立可用时间的调整价与披露数据。模拟冲击写入派生快照。
- [历史市场](historical_market.md) 提供数据格式和可运行验收示例。真实市场覆盖由接入的数据包决定。
